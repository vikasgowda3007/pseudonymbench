# MaskGate gap check: do existing reversible PII-masking LLM proxies publish rigorous evaluation?

Date: 2026-10-19 (GitHub data pulled 2026-10-19/20). Method: shallow `git clone` of each repo, then `git grep` over docs, benchmark dirs and scripts, plus `gh api` for stars and dates, plus PyPI JSON and WebFetch for non-GitHub sources.

Labels used below: **[EVIDENCE]** = read in a primary source (path given). **[INFERENCE]** = my conclusion from absence or from reading. **[UNVERIFIED]** = could not check.

Link convention: `owner/repo:path#Lnn` means that path at the default branch HEAD I cloned (path and line numbers are from the clone; all but one repo use `main`/`master`). Prefix with `https://github.com/owner/repo/blob/<default-branch>/`.

The four criteria:
- (a) proxy overhead p50/p99 under open-loop load
- (b) streaming time-to-first-token (TTFT) delta
- (c) per-entity precision/recall on a redistributable dataset
- (d) field-coverage matrix (which JSON fields and tool-call args are masked)

Grades: yes / partial / no. "Partial" is spelled out in the notes.

## Verdict

**The gap is PARTIAL, not closed. [INFERENCE from the table above]**

- **(d) field coverage is the most-covered item.** PrivAiTe publishes an exact scanned / not-scanned list pinned to code by a test (`docs/gateway.md` L122-156), and LLM-Shield-Proxy publishes a per-field probe. Neither is a cross-vendor matrix with a conformance harness, so a matrix of "which fields, which proxy, verified by test" is still unmet but no longer empty ground.
- **(a) is partly met only in form.** Tamga is the only one using true open-loop load (k6 constant-arrival-rate) with p50/p99, but on a non-PII payload with no direct baseline and no streaming. Nobody I found publishes masking overhead = (proxy e2e) minus (direct-to-provider) at matched open-loop rate with PII-bearing and tool-call payloads. LLM-Shield-Proxy explicitly disclaims end-to-end numbers.
- **(b) TTFT delta: nobody publishes it.** Script-level hooks exist (AegisGate `stream_ttfb`, PrivAiTe `ttfb_s`, LLM-Shield-Proxy "first useful content" probe) but no result file contains a TTFT delta against a direct baseline. veil reports a restore-time ratio, which is not TTFT. This is the clearest remaining gap.
- **(c) per-entity P/R on redistributable data: weak.** PasteGuard ships a redistributable harness but no results; veil publishes per-detector P/R but on a self-generated saturated synthetic set; PrivAiTe has per-entity numbers on AI4Privacy, which it cannot redistribute; daslabhq has per-label F1 on Nemotron-PII (licence unverified). No repo ties per-entity P/R to the proxy path with a redistributable corpus.
- **Direct competitor risk:** PrivAiTe (and secondarily LLM-Shield-Proxy) already occupy the "rigorous benchmark" positioning, and PrivAiTe's `docs/comparison.md` already frames tool-call coverage as a differentiator. A claim of "first to publish" is safe only for the specific combination (open-loop overhead + streaming TTFT delta + per-entity P/R on redistributable data + field matrix), not for any single item.
